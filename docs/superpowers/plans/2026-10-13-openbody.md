# openBody Implementation Plan (roadmap + Phase 1 detail)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans (the chosen method is Native; the owner said "start building"). Steps use checkbox (`- [ ]`) syntax for tracking. Phases 2–9 are planned at task level here. Each one gets a code-level addendum (`docs/superpowers/plans/2026-10-13-openbody-phase-N.md`) written right before it starts, once the files it touches have been read.

**Goal:** Turn the openGym fork into openBody, a calisthenics and mobility tracker with skill ladders, guided mobility flows, flexibility assessments, built-in programs, and a library and workouts by muscle and area.

**Architecture:** Layer onto the existing engine, data-first:
- **Content:** new JSON content types in `catalogue/`, compiled by `scripts/catalogue/build.mjs` into `frontend/src/lib/content/`.
- **Logic:** new pure modules in `frontend/src/lib/`, each with a co-located test.
- **Screens:** vertical slices in `frontend/src/features/<name>/`.
- **Rules:** no new runtime dependencies, and all new state keys are absent-safe.

**Tech Stack:** React 19, Vite 8, react-router 7, Zustand 5, Vitest 4 + happy-dom, Node 22 `node:http` API, `node --test`, Docker Compose + nginx.

**Spec:** `docs/superpowers/specs/2026-10-13-openbody-design.md`

## Global Constraints

- Frontend runtime deps stay: React, react-dom, react-router-dom, zustand (+ existing Capacitor). **No new dependencies.**
- Every user-visible string goes through a literal `t('…')` call (`frontend/scripts/check-source-strings.mjs` enforces it). English is the source.
- Training logic (anything that decides what you do next or reads a session back) = a pure helper in `frontend/src/lib/` with a `*.test.js` beside it.
- New store keys must read correctly when absent: `skillOverrides: {}`, `assessments: []`, `program: null`.
- Internal identifiers are not renamed: `gym_state_v1`, cookie names, `DATA_DIR` file names, `OPENGYM_*` env vars, lowercase `opengym` log tags.
- New exercise ids start at **20000** (upstream max is 12018). Ids are permanent.
- New exercise text: lowercase names, no em dash (—), 2–7 instruction steps, values from `scripts/catalogue/validate.mjs` lists.
- Gym visual media (`catalogue/media/`) is never modified and never processed by AI tooling. New media lives in `catalogue/media-open/` with `SOURCES.md`.
- Palette: accent teal `#2dd4bf` (dark) / `#0d9488` (light), skill secondary amber `#f59e0b` (dark) / `#b45309` (light), WCAG AA contrast for every text-on-fill pair.
- Commit locally on `feat/openbody` after each verified phase (standing approval). Never push without asking.
- Changelog per session in `changelogs/YYYY-MM-DD-*.md`; lessons in `lessons-learned/` + `INDEX.md`.

## Review Focus

1. **Existing openGym state or backup loaded into openBody.** It must load, without crashing and without losing data. The new keys being absent must not throw anywhere (Phase 1, Task 1.3 test).
2. **A user who already has equipment profiles.** The Calisthenics profile must be added for new users only. Existing users must not have their active profile switched silently (Task 1.3 test).
3. **A ladder or flow referencing an exercise id that does not exist,** whether a custom one or one deleted from user data. It must be rejected at build and skipped at runtime, never crash (Phase 2 validator test, Phase 4/5 runtime tests).
4. **A flow interrupted mid-hold** (backgrounded, reloaded). On return it must resume where it was, not restart or double-log (Phase 5 reducer test).
5. **Enrolling in a program when routines and a schedule already exist.** It must ask before replacing the schedule and must never delete user routines (Phase 7 test).

## Content schemas (contract for Phase 2 content and Phases 3–7 code)

Routine-entry shape (`ExItem`), the same one `routines[].ex[]` uses:
`{ "id": "<exId>", "sets": 3, "reps": 8 }`, or a hold `{ "id", "sets": 3, "mode": "time", "sec": 30 }`.
Optional: `"side": true` (per side), `"repsMin": 6` (range bottom), `"bodyweight": true`.

**`catalogue/areas.json`**
```json
{ "areas": [ { "id": "hips", "name": "Hips", "muscles": ["gluteal", "hip-flexors", "adductors"] } ] }
```
Ids: `neck, shoulders, thoracic, lower-back, hips, groin, hamstrings, hip-flexors-quads, calves-ankles, wrists-forearms, core`. Muscles are from `MUSCLES` in validate.mjs.

**`catalogue/skills/<id>.json`**
```json
{ "id": "front-lever", "name": "Front lever", "family": "pull", "description": "…",
  "steps": [ { "exId": "1234", "label": "Tuck front lever", "mode": "time",
               "target": { "sets": 3, "sec": 10 }, "unlock": { "sets": 3, "sec": 15, "sessions": 2 },
               "cue": "…" } ] }
```
`family ∈ push|pull|legs|core|balance`. `mode ∈ reps|time`. For a reps step, `target`/`unlock` carry `reps`.

**`catalogue/workouts/<id>.json`**
```json
{ "id": "pull-beginner", "name": "Pull: Beginner", "kind": "muscle", "group": "back",
  "level": "beginner", "goal": "strength", "minutes": 30, "description": "…", "ex": [ExItem] }
```
- `kind ∈ muscle|area`.
- For `kind: muscle`, `group ∈ chest|back|shoulders|arms|core|legs|full-body`. For `kind: area`, `group` is an area id.
- `level ∈ beginner|intermediate|advanced`, `goal ∈ strength|skill|mobility|conditioning`.

**`catalogue/flows/<id>.json`**
```json
{ "id": "hip-opener", "name": "Hip opener", "description": "…", "areas": ["hips"], "level": "beginner",
  "transitionSec": 5, "items": [ { "exId": "1234", "sec": 45, "side": true, "cue": "…" } ] }
```

**`catalogue/assessments/<id>.json`**
```json
{ "id": "toe-touch", "name": "Standing toe touch", "unit": "cm", "better": "higher", "sided": false,
  "range": [-40, 40], "areas": ["hamstrings", "lower-back"], "instructions": ["…"],
  "bands": [ { "label": "poor", "below": -10 }, { "label": "fair", "below": 0 },
             { "label": "good", "below": 10 }, { "label": "great", "below": 20 }, { "label": "elite" } ] }
```
- Bands ascend by value. A value falls in the first band whose `below` is greater than it, and the last band is open-ended.
- When `better: "lower"`, the labels run from elite down to poor instead.
- `unit ∈ cm|deg|s`.

**`catalogue/programs/<id>.json`**
```json
{ "id": "fundamentals", "name": "Fundamentals", "level": "beginner", "weeks": 8, "description": "…",
  "assessEveryWeeks": 4,
  "routines": [ { "key": "a", "name": "Full body A", "emoji": "pullup", "ex": [ExItem], "ladders": { "0": "front-lever" } } ],
  "schedule": [ [1, "a"], [3, "b"], [5, "a"] ],
  "flows": [ [0, "morning-flow"] ] }
```
- Schedule days use the starter-plan convention (`lib/starter.js`: weekday index, 1 = Monday).
- `ladders` maps an entry index to a skill id. That entry gets `ladder: skillId` and the `ladder` policy.
- `flows` schedules guided flows as day reminders.

## Deviations from this plan (recorded during execution, 2026-10-13)

- **Skill ladders are a layer in front of the progression engine, not a `ladder` policy inside it.**
  - `lib/ladder.js` swaps the routine entry to the next variation (`applyLadders` at session start and finish).
  - Within a step, the existing `time` and `double` policies run.
  - Reason: `nextPrescription` is about 300 lines of bug-fixed edge cases, and a layer reuses them without touching them.
- **The running guided flow is device-local** (`features/flows/flow-store.js`, localStorage), not `S.activeFlow`. A synced copy let a second tab or device log the same flow again (review finding).
- **`skillOverrides` stores `{ v, _ts }` per skill** (a stamped map), not a bare index. `v` is "the step I'm on", so "I can already do step i" stores i + 1.
- **`assessments` merge as a union by id** with deletion tombstones. The rules are mirrored in `api/sync-stamps.js`.
- **Programs put laddered slots exactly on the current step** (`onCurrentStep`) at enrollment. `ladderedEntry` leaves an off-ladder exercise alone.
- **Docker builds local `openbody-*:local` images** (`pull_policy: build`). Upstream's ghcr.io images are openGym.
- **Five upstream API tests now pin the date** (fixture dates expired 2026-10-13, identically on pristine upstream).
